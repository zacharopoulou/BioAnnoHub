# mTOR pathway event corpus - local benchmark data

The mTOR pathway event corpus has **no splits**: it is one small corpus of
60 documents. So the whole corpus is in `mtor.jsonl`, which is committed to
this repo and used for testing annotators, and nothing is left out via
`.gitignore`. To regenerate it locally:

```
uv run python benchmarks/scripts/mtor.py
```

No extra dependencies are needed. The corpus is not on Hugging Face, so the
script downloads the original brat standoff files from GitHub
(`https://github.com/openbiocorpora/mtor-pathway`, pinned to commit
`59694bd`) and converts them to the same `bigbio_kb` layout as the other
benchmarks. It checks every entity offset against the text while
converting.

The corpus (Ohta, Pyysalo and Tsujii, 2011, "From Pathways to Biomolecular
Events") is a GENIA project event corpus built from the **mTOR signalling
pathway**: 60 PubMed abstracts, each with a title passage and an abstract
passage. The text is plain ASCII. No normalization.

It annotates these entity types:

| Type | Mentions | Examples |
|---|---|---|
| Protein | 1,483 | mTOR, PRAS40, beta-catenin, TSC2 |
| Complex | 201 | mTORC1, mTORC2, NF-kappaB |
| Drug | 42 | rapamycin, tamoxifen |
| Simple_molecule | 26 | calcium, GTP, cAMP |
| RNA | 12 | rRNA, siRNA, tRNAs |
| Ion | 5 | Ca2+, Ca(2+) |
| Tag | 3 | GST (a protein tag used in experiments) |
| Receptor | 1 | receptor |

## How the file is built

Each document has a single `.ann` file that holds both the entities and
the event trigger words (such as *phosphorylation* or *binding*, 1,065 of
them). A text annotation is an event trigger when an event line uses it as
its trigger, and those are left out. The events themselves are not
included either.

## Notes

- **The annotations are complete.** Unlike GREC or CoMAGC, entities were
  annotated whether or not they take part in an event: 416 of the 1,483
  proteins are not in any event but are still annotated, and less than 1%
  of the occurrences of annotated protein names are missing an
  annotation.
- **The `Entity` type is left out** (148 mentions). It was only annotated
  when it takes part in an event (147 of 148), so it is not complete.
- **Protein complexes are a separate type.** Names such as *mTORC1* are
  `Complex`, not `Protein`. When scoring a gene tagger, decide whether
  complexes count as genes.
- 60 documents is a small corpus, so scores will vary more than on the
  larger benchmarks.

## Known training overlap

- **BENT** `BENT-PubMedBERT-NER-Gene`: its model card lists the mTOR
  pathway event corpus (type "Protein") without saying which documents.
  There is no split, so BENT has very likely seen these documents.

`MTOR_ANALYTICS_SUMMARY.md` is generated by
`benchmarks/analytics/mtor_analytics.py` and documents the corpus shape
(counts, entity types, normalization coverage, top mentions).
