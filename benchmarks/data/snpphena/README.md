# SNPPhenA - local benchmark data

Only `test.jsonl` is committed to this repo. It is the official held-out
evaluation split, used for testing annotators.

`train.jsonl` is intentionally **not** shipped here (see `.gitignore`).
SNPPhenA does not have a validation split. Anyone who needs the train
split can regenerate the full corpus locally:

```
uv run python benchmarks/scripts/snpphena.py
```

No extra dependencies are needed. The corpus is not on Hugging Face, so the
script downloads the brat version from figshare (`SNPPhenA_BRAT.zip`,
licence CC BY 4.0) and converts it to the same `bigbio_kb` layout as the
other benchmarks. It checks every entity offset against the text while
converting.

SNPPhenA (Bokharaeian et al., 2017, "SNPPhenA: a corpus for extracting
ranked associations of single-nucleotide polymorphisms and phenotypes from
literature") is about **genetic variants (SNPs) and the phenotypes they are
associated with**. Each document is **one sentence** from a PubMed
abstract, named `Abs_<n>-s<sentence>`:

| Split | Sentences | Abstracts | Entities |
|---|---|---|---|
| train | 362 | 270 | 1,189 |
| test | 121 | 90 | 402 |

No normalization. The SNP-phenotype association relations are not
included.

## Entity types

| Type | Examples |
|---|---|
| SNP | rs4680, rs1799971, Val158Met |
| Phenotype | schizophrenia, alcohol dependence, prostate cancer |

`SNP` covers dbSNP identifiers (`rs` numbers) and also variant names such
as *Val158Met*. For a variant tagger use `SNP`, and for a disease tagger
use `Phenotype` (it is mostly diseases, but also traits such as *hot
flashes*).

## Notes

- **The sentences were chosen because they state SNP-phenotype
  associations**, and every annotated SNP and phenotype takes part in one.
  We checked that this does not leave many entities unannotated: in test,
  195 `rs` numbers in the text are annotated and only 2 are not, and only
  2 repeated phenotype names are missing an annotation. A phenotype that
  is mentioned but not associated with an SNP may still be unannotated in
  a few cases.
- **Modality and negation annotations are left out.** The files also mark
  `Modality_Marker`, `Negation_Cue` and `Negation_Scope`, which are not
  named entities.
- **The text has non-breaking spaces.** It is kept exactly as released,
  and some mentions contain a non-breaking space (for example
  `lung\xa0cancer`). Offsets are unaffected, but a comparison by text
  should treat non-breaking spaces as normal spaces.
- Every sentence has annotations.

## Known training overlap

- **BENT** `BENT-PubMEdBERT-NER-Variant`: its model card lists SNPPhenA
  (type "SNP") without saying which splits, so it may have seen the test
  set.

`SNPPHENA_ANALYTICS_SUMMARY.md` is generated by
`benchmarks/analytics/snpphena_analytics.py` from a full local download and
documents the entire corpus shape (counts, entity types, normalization
coverage, top mentions), even though only `test.jsonl` lives here.
