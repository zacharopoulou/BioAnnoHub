# Mantra GSC (English) - local benchmark data

The Mantra Gold Standard Corpus (Kors et al., 2015) has **no train/test
split**. It covers 5 languages; only the **English** texts are used here,
because the annotators in this project work on English. Each kind of text
is committed as its own file, used for testing annotators, and nothing is
left out via `.gitignore`. To regenerate them locally:

```
uv sync --extra benchmarks
uv run python benchmarks/scripts/mantra.py
```

That builds the files with the Hugging Face loader (`bigbio/mantra_gsc`,
one config per part). The loader gets the original files from GitHub
(`https://github.com/mi-erasmusmc/Mantra-Gold-Standard-Corpus`).

| File | Content | Documents | Mentions |
|---|---|---|---|
| `mantra_en_medline.jsonl` | titles of Medline abstracts | 400 | 1,177 |
| `mantra_en_emea.jsonl` | sentences from EMEA drug labels | 100 | 433 |
| `mantra_en_patents.jsonl` | claims from biomedical patents | 50 | 353 |

The documents are short: a Medline title is about 70 characters, an EMEA
sentence about 110 and a patent claim about 320.

## What is annotated

Every mention is linked to a **UMLS concept** (CUI, for example
`C0001527`), and its type is the concept's **UMLS semantic group**:

| Type | Meaning |
|---|---|
| DISO | disorders: diseases, symptoms, findings |
| CHEM | chemicals and drugs, including proteins and genes as substances |
| PROC | procedures, such as treatments and tests |
| LIVB | living beings: organisms, people, animals |
| ANAT | anatomy |
| PHYS | physiology |
| PHEN | phenomena |
| OBJC | objects |
| DEVI | devices |
| GEOG | geographic areas |

For a disease tagger use `DISO`, for a chemical tagger `CHEM`, and for a
species tagger `LIVB`. Note that `LIVB` also includes people (such as
*patients* or *children*), not only species names.

## Fixes made by the script

1. **Wrong text encoding on Windows.** The loader reads the text files
   with the computer's default encoding (cp1253 on a Greek Windows PC)
   instead of UTF-8. That garbled characters such as the é in *México*
   (and shifted every offset after it) or crashed. The script makes the
   loader read them as UTF-8. After this, every mention matches its text.
2. **A few types are semantic type names instead of group codes.** 17
   annotations in the original data use a UMLS semantic type name, for
   example `Manufactured Object` (*schools*) or `Mental or Behavioral
   Dysfunction` (*violence*). Each of these belongs to one semantic group,
   so the script replaces it with that group (OBJC, DEVI, PROC, DISO or
   CHEM). One EMEA mention keeps the type `OBJC|CHEM`, because the original
   data gives it both groups.

## Notes

- The other languages (French, German, Spanish, Dutch) are left out. They
  are parallel texts, so their content is the same as the English files.
- 24 documents have no annotations. They are kept, because any concept an
  annotator finds in them is a false positive.
- Mantra annotates concepts from many semantic groups, including general
  ones such as PROC and OBJC, so it tests broad concept recognition, not
  only the usual gene, disease and chemical types.

## Known training overlap

- **BENT**: its model cards list Mantra for the Disease model (type
  "DISO", **train, dev and test** sets) and the Anatomical model (type
  "ANAT"). Mantra has no official split, so BENT made its own and has seen
  at least part of these documents. (The Organism model card also lists
  Mantra with type "DISO", which looks like a copy error; organisms are
  `LIVB`.)

`MANTRA_ANALYTICS_SUMMARY.md` is generated by
`benchmarks/analytics/mantra_analytics.py` and documents each part
(counts, entity types, normalization coverage, top mentions).
