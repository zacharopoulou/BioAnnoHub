# JNLPBA - local benchmark data

Only `test.jsonl` is committed to this repo. It is the official held-out
evaluation split, used for testing annotators.

`train.jsonl` is intentionally **not** shipped here (see `.gitignore`).
JNLPBA does not have a validation split. Anyone who needs the train split
can regenerate the full corpus locally:

```
uv sync --extra benchmarks
uv run python benchmarks/scripts/jnlpba.py
```

That reads the sentence-level tokens + BIO tags from Hugging Face
(`jnlpba/jnlpba`, the same data as `bigbio/jnlpba`'s `jnlpba_source`
config) and converts them into proper documents: each row is one sentence
with its text in `passages`, and the B-/I- tags are merged into one entity
per mention with real character offsets. The `jnlpba_bigbio_kb` config is
not used because it is a broken conversion (empty passages, one entity per
token, tag indices as types).

**Split names:** on Hugging Face the official test set is published under
the name `validation`. We compared it with the original test file
(`Genia4EReval2.iob2` from the JNLPBA 2004 shared task): all 3,856
sentences are identical, tokens and tags. So the script saves it as
`test.jsonl`, its real name. The Hugging Face `train` split is identical
to the official training file (18,546 sentences).

JNLPBA annotates five molecular-biology types (protein, DNA, RNA,
cell_line, cell_type); no normalization, no relations. The entity counts
in `JNLPBA_ANALYTICS_SUMMARY.md` match the official counts from the shared
task paper (Collier and Kim, 2004).

Notes:

- JNLPBA only releases tokens, not the original sentence text, so the text
  is rebuilt by joining the tokens with single spaces. Annotators therefore
  see tokenized text such as `( GR )` or `[ 3H ] -thymidine` instead of the
  original spacing. Every entity offset matches this rebuilt text.
- The sentences come from 2,000 training and 404 test PubMed abstracts
  (from the GENIA corpus), but the abstract boundaries are not kept, so
  each document is one sentence.

`JNLPBA_ANALYTICS_SUMMARY.md` is generated by
`benchmarks/analytics/jnlpba_analytics.py` from a full local download and
documents the entire corpus shape (counts, entity types, normalization
coverage, top mentions), even though only `test.jsonl` lives here.
