# AnatEM - local benchmark data

Only `test.jsonl` is committed to this repo. It is the held-out
evaluation split, used for testing annotators.

The other split(s) (train, validation) are intentionally **not** shipped here (see `.gitignore`). Regenerate the full corpus locally:

```
uv run python benchmarks/scripts/anatem.py
```

No extra dependencies are needed. The script fetches the official distribution
from NaCTeM (`https://www.nactem.ac.uk/anatomytagger/AnatEM-1.0.2.tar.gz`,
9.2 MB, CC BY-SA 3.0) and converts its brat standoff annotations to bigbio_kb.

## AnatEM, not AnEM

This is **AnatEM** (Pyysalo and Ananiadou, 2014), the corpus Stanza's `anatem`
model is trained on, not the smaller **AnEM** (Ohta et al., 2012) published as
`bigbio/an_em`. AnEM has 11 entity types, AnatEM has 12, the extra one being
`Cancer`.

## Splits

The corpus ships `train` / `devel` / `test`; the script writes `devel` as
`validation.jsonl` to match the naming used by every other corpus here.

| Split | Documents | Mentions |
|---|---|---|
| train | 606 | 6,946 |
| validation | 202 | 2,139 |
| test | 404 | 4,616 |
| **total** | **1212** | **13,701** |

## Entity types

Twelve granularity-based types, assigned per the Common Anatomy Reference
Ontology. Counts below are for the committed `test.jsonl`:

| type | n |
|---|---|
| Cell | 1429 |
| Cancer | 1117 |
| Multi-tissue_structure | 551 |
| Organ | 306 |
| Cellular_component | 285 |
| Tissue | 256 |
| Organism_substance | 243 |
| Pathological_formation | 148 |
| Organism_subdivision | 111 |
| Immaterial_anatomical_entity | 96 |
| Anatomical_system | 39 |
| Developing_anatomical_structure | 35 |

Types are stored exactly as the corpus assigns them; nothing is merged or
renamed. No normalization: entities carry spans and types only.

## Open question for scoring

Stanza's `anatem` NER model predicts a single flat `ANATOMY` label, and
**whether `Cancer` counts as anatomy is an open decision** that materially
changes the result: it is 1,117 of the 4,616 test mentions. This is deliberately
left unresolved here.

For reference, Stanza reports 88.18 entity micro-averaged test F1 on AnatEM.

## Known training overlap

Some annotators were trained on AnatEM. Their score on `test.jsonl` is only
fair if they never saw the test split:

- **Stanza** `anatem` model: trained on the AnatEM train split, so its
  test score is fair.
- **BENT** `BENT-PubMedBERT-NER-Anatomical`: its model card lists AnatEM
  among its training data without saying which splits, so it may have seen
  the test set.

`ANATEM_ANALYTICS_SUMMARY.md` is generated by
`benchmarks/analytics/anatem_analytics.py` from a full local download and
documents the entire corpus shape (counts, entity types, normalization
coverage), even though only test.jsonl lives here.
