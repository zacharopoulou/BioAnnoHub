# BC4CHEMD - local benchmark data

Only `test.jsonl` is committed to this repo. It is the official held-out
evaluation split, used for testing annotators.

`train.jsonl` and `validation.jsonl` are intentionally **not** shipped here
(see `.gitignore`). Anyone who needs them can regenerate the full corpus
locally:

```
uv sync --extra benchmarks
uv run python benchmarks/scripts/bc4chemd.py
```

That downloads all three splits from Hugging Face (`bigbio/chemdner`,
config `chemdner_bigbio_kb`) into this directory. The loader gets the
corpus from NCBI (`BC7T2-CHEMDNER-corpus_v2.BioC.xml.gz`), not from the
BioCreative website, so it still works.

BC4CHEMD is the **BioCreative IV CHEMDNER** corpus (the two names are the
same corpus): 10,000 PubMed abstracts (3,500 train, 3,500 validation,
3,000 test) with every chemical mention annotated. Each document has a
title passage and an abstract passage. One entity type (`Chemical`), no
normalization, no relations.

Notes:

- **This is NLM's "v2" version** of CHEMDNER, prepared for BioCreative VII.
  Its mention counts differ slightly from the original 2015 paper
  (train 29,462 vs 29,478, validation 29,523 vs 29,526, test 25,342 vs
  25,351). We checked the raw v2 files: train and validation match them
  exactly.
- **4 test annotations are dropped on purpose.** They have zero length
  (no text at all) in the raw file, so they are broken annotations, not
  real mentions. The loader also skips the document-level
  `MeSH_Indexing_Chemical` tags, which have no position in the text.
- The original corpus splits chemicals into 7 classes (SYSTEMATIC,
  TRIVIAL, FORMULA, ABBREVIATION, FAMILY, IDENTIFIER, MULTIPLE). The
  bigbio format keeps only the single type `Chemical`.
- About 1 in 6 abstracts (523 in test) have no chemical mentions. They
  are kept, because any chemical an annotator finds in them is a false
  positive.
- `test.jsonl` is large (7.6 MB), the biggest committed file here after
  BioID's `bioid.jsonl`.

## Known training overlap

- **BENT** `BENT-PubMedBERT-NER-Chemical`: its model card lists both
  CHEMDNER and BC4CHEMD with their **train, dev and test** sets, so it has
  seen this test set and its score here is not a fair test.

`BC4CHEMD_ANALYTICS_SUMMARY.md` is generated by
`benchmarks/analytics/bc4chemd_analytics.py` from a full local download and
documents the entire corpus shape (counts, entity types, normalization
coverage, top mentions), even though only `test.jsonl` lives here.
