# tmVar3 - local benchmark data

tmVar3 has **no splits**: the Hugging Face dataset card says "This
dataset does NOT have splits". So unlike the other benchmarks here, there
is no `test.jsonl`: the whole corpus (500 documents) is in `tmvar_v3.jsonl`,
which is committed to this repo and used for testing annotators, and
nothing is left out via `.gitignore`. To regenerate it locally:

```
uv sync --extra benchmarks
uv run python benchmarks/scripts/tmvar_v3.py
```

That downloads the corpus from Hugging Face (`bigbio/tmvar_v3`, config
`tmvar_v3_bigbio_kb`) into this directory. The loader still has to name a
split, so it serves all 500 documents as `test`; the script saves them as
`tmvar_v3.jsonl` because that name is only a convention, not an official
held-out test set. Documents are PubMed
abstracts (title + abstract). No relations.

tmVar3 has ten entity types:

- variants: SNP, DNAMutation, ProteinMutation, OtherMutation, DNAAllele,
  ProteinAllele, AcidChange
- context: Gene, Species, CellLine

Gene mentions are normalized to NCBI Gene. Variant mentions are normalized
to dbSNP and to their corresponding gene.

Note on normalization in the `bigbio_kb` config:

- Under `db_name: dbSNP` it stores two different things: real rsIDs
  (digits only, e.g. `2234671`) and tmVar normalized strings (e.g.
  `c|SUB|G|Ex2+860|C`). Only the digit-only values are dbSNP IDs.
- `NCBI Gene` IDs on variant mentions identify the gene the variant is on,
  not the variant itself.
- Species and CellLine mentions have no normalization (the NCBI Taxonomy
  IDs in the original corpus are dropped), and ClinGen allele IDs are
  dropped too.
- One document (PMID 21904390) has wrong offsets in the original file;
  the Hugging Face loader corrects them, and every offset in
  `tmvar_v3.jsonl` matches the text.

`TMVAR_V3_ANALYTICS_SUMMARY.md` is generated by
`benchmarks/analytics/tmvar_v3_analytics.py` and documents the corpus shape
(counts, entity types, normalization coverage, variant IDs, top mentions).
