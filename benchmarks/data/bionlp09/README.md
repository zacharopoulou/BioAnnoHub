# BioNLP09 - local benchmark data

Only `test.jsonl` is committed to this repo. It is the official held-out
evaluation split, used for testing annotators.

`train.jsonl` and `validation.jsonl` are intentionally **not** shipped here
(see `.gitignore`). Anyone who needs them can regenerate the full corpus
locally:

```
uv sync --extra benchmarks
uv run python benchmarks/scripts/bionlp09.py
```

That downloads all three splits from Hugging Face
(`bigbio/bionlp_shared_task_2009`, config
`bionlp_shared_task_2009_bigbio_kb`) into this directory. The loader gets
the original files from the GENIA project at NaCTeM.

BioNLP09 is the corpus of the BioNLP Shared Task 2009 on event extraction
(GENIA event task): 1,210 PubMed abstracts (800 train, 150 validation, 260
test) about molecular biology, mostly transcription factors in human blood
cells. Each document is one passage with the title and abstract together.
For NER it has one entity type, `Protein`, which covers genes and their
products. No normalization.

Notes:

- **The test set has entities but no events.** BioNLP09 is an event
  extraction task. The protein annotations (`.a1` files) were given to
  participants as input and only the events (`.a2` files) were kept hidden,
  so the test proteins are real gold annotations and can be used for NER.
  The `events` field is empty in `test.jsonl`.
- **Train and validation have an extra `Entity` type** (434 and 94
  mentions), for example *promoter*, *nuclear* or *tyrosine*. It comes from
  the event files (`.a2`) and was only annotated when it takes part in an
  event, so it is not complete and does not appear in test. Leave it out
  when comparing with test.
- 44 training abstracts have no proteins at all. This is also the case in
  the original files, so they are kept.

## Known training overlap

- **BENT** `BENT-PubMedBERT-NER-Gene`: its model card lists BioNLP09
  without saying which splits, so it may have seen the test set.

`BIONLP09_ANALYTICS_SUMMARY.md` is generated by
`benchmarks/analytics/bionlp09_analytics.py` from a full local download and
documents the entire corpus shape (counts, entity types, normalization
coverage, top mentions), even though only `test.jsonl` lives here.
