# miRNA - local benchmark data

Only `test.jsonl` is committed to this repo. It is the official held-out
evaluation split, used for testing annotators.

`train.jsonl` is intentionally **not** shipped here (see `.gitignore`).
The miRNA corpus does not have a validation split. Anyone who needs the
train split can regenerate the full corpus locally:

```
uv run python benchmarks/scripts/mirna.py
```

No extra dependencies are needed. The script downloads the two original
XML files from Fraunhofer SCAI (`miRNA-Train-Corpus.xml` and
`miRNA-Test-Corpus.xml`) and converts them itself, in the same `bigbio_kb`
layout as the other benchmarks. It checks every entity offset against the
text while converting.

The miRNA corpus ("miRNA-Test-Corpus", Bagewadi et al., 2014) has 301
PubMed abstracts (201 train, 100 test) that mention **microRNAs**. Each
document has a title passage and an abstract passage. No normalization.

It annotates 5 entity types:

| Type | Meaning | Examples |
|---|---|---|
| Specific_miRNAs | a named microRNA | miR-21, miR-145, let-7 |
| Non-Specific_miRNAs | microRNAs in general | miRNA, microRNAs |
| Genes/Proteins | genes and proteins | GRN, XIAP, Tau |
| Diseases | diseases | glioblastoma, stroke, cancer |
| Species | organisms, including people | human, mice, patients |

## Why the Hugging Face loader is not used

The Hugging Face loader (`bigbio/mirna`) has three problems:

1. **It drops sentences.** Every sentence without annotations is left
   out (183 in train, 50 in test), so the documents are missing part of
   their text.
2. **The sentences are in the wrong order.** The original XML stores the
   sentences of each abstract out of order (for example s3, s4, s2, s5,
   s1, s0), and the loader keeps that order. This script sorts them by
   their sentence number, which gives back the real abstract: s0 is the
   title, then the abstract sentences in order.
3. **Its normalization IDs are not real.** It fills the normalization
   field with each annotation's own ID (such as `miRNA-corp.d0.s1.e0`),
   not a database link. The corpus has no normalization, so the field is
   left empty here.

## Notes

- **Relation triggers are left out.** The XML also marks words that
  signal a relation, such as *regulate* or *predicted to target*
  (`Relation_Trigger`, 625 in test). They are not named entities, so they
  are not included. The corpus's miRNA-gene and miRNA-disease relations
  are not included either.
- The end offsets in the XML include the last character of the mention,
  so the script adds 1 to every end offset.
- For a gene tagger, microRNAs are genes too, so decide whether
  `Specific_miRNAs` should count as genes when scoring. `Non-Specific_miRNAs`
  are general words (*microRNAs*) that most taggers will not tag.

## Known training overlap

- **BENT**: its model cards list the miRNA-Test-Corpus for the Gene model
  (type "Genes/Proteins"), the Disease model (type "Diseases", **train,
  dev and test** sets) and the Organism model (type "species"). The
  Disease model has seen this test set; the others do not say which
  splits.

`MIRNA_ANALYTICS_SUMMARY.md` is generated by
`benchmarks/analytics/mirna_analytics.py` from a full local download and
documents the entire corpus shape (counts, entity types, normalization
coverage, top mentions), even though only `test.jsonl` lives here.
